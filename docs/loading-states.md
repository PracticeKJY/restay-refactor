# 페이지 로딩 UI

별도의 로딩 화면 대신 현재 페이지의 레이아웃 안에서 스켈레톤과 콘텐츠가 교체된다.
인증, 데이터 요청, 결제, 라우팅 정책은 변경하지 않는다.

## 적용 범위

| 화면 | 로딩 처리 |
| --- | --- |
| 메인 / 필터 결과 | HomeClient의 소개·검색·카테고리·섹션 구조를 재사용하고 이미지·숙소 목록·개수만 스켈레톤 표시 |
| 숙소 상세 | 기존 Container·갤러리·소개·예약 카드 CSS를 공유하는 상세 스켈레톤 |
| 예약 | 기존 좌측 예약 정보 / 우측 숙소·요금 카드 배치 유지 |
| 위시리스트 / 여행 | 실제 페이지 제목과 설명, 동일한 반응형 카드 그리드 유지 |
| 메시지 / 대화방 | 목록·대화·입력 영역 배치 유지, 조회 중인 목록과 대화만 스켈레톤 표시 |
| 지도 | 기존 지도 높이를 유지한 스켈레톤 표시 |
| 숙소 이미지 | 메인·목록·상세·예약에서 이미지가 로드될 때까지 Restay 플레이스홀더 유지 |

`app/[locale]/(home)/loading.tsx`와 각 하위 경로의 `loading.tsx`가 페이지별 로딩 경계를 제공한다.
홈 페이지와 로딩 경계는 `(home)` route group 안에 두어 다른 페이지 이동 중 홈 스켈레톤이 표시되지 않게 한다. 이 그룹 이름은 URL에 포함되지 않으므로 `/`, `/en` 및 검색 쿼리는 유지된다.
위시리스트와 채팅의 클라이언트 요청에도 같은 스켈레톤을 사용한다.
기존 Spinner / Loading import는 카드 스켈레톤으로 연결해 별도 스피너 화면이 다시 나타나지 않게 한다.
폼 제출, 언어 변경 등 기존 화면을 유지하는 작업의 버튼 비활성화·처리 문구는 유지한다.

`LoadingRegion`은 번역된 상태 문구를 스크린리더에 제공하고 장식용 도형은 숨긴다.
`prefers-reduced-motion`에서는 애니메이션을 중지한다. 이미지 실패 시에도 애니메이션을 중지한다.

## 확인한 결과

- 변경 전: 공통 로딩 문구, 메인의 별도 로딩 카드, 위시리스트 스피너, 채팅·지도 로딩 문구가 혼재.
- 변경 후: 메인/필터/상세/예약/위시리스트/여행/메시지/대화방을 한국어·영어와 320/768/1440px에서 렌더링해 총 48개 조합의 스켈레톤 표시 및 가로 넘침 없음을 확인.
- UI 확인용 임시 경로에서 로딩 상태를 강제로 렌더링했으며, 해당 임시 페이지는 최종 코드에서 제거.
- 이미지 요청을 지연했을 때 플레이스홀더를 유지하고, 완료 시 실제 이미지로 전환. 테스트 이미지 영역은 전후 모두 300×200px.
- 이미지 실패 시 정적인 플레이스홀더 유지, 움직임 줄이기 설정에서 애니메이션 중지 확인.
- 실제 메인(ko/en), 숙소 상세, 비로그인 위시리스트·여행·메시지 경로의 HTTP 200 응답 확인.
- 로그인된 사용자 데이터 조회와 실제 결제는 브라우저에서 실행하지 않음. 인증·채팅·예약 계약은 기존 자동 테스트로 회귀 검사.
- 로딩 표현을 변경한 작업이며 LCP/TTFB 등 속도 개선 수치는 측정하거나 주장하지 않음.

검증 명령: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.
`tests/loading.test.cjs`는 상태 안내의 접근성, 이미지 주소 변경, 로드 완료 및 실패 전환을 검사한다.
전체 자동 테스트 47개와 ESLint, TypeScript, 프로덕션 빌드가 통과했다.
홈 로딩 경계 분리 후 한국어·영어에서 위시리스트 → 여행 → 메시지 → 위시리스트 탭 이동을 응답 지연과 함께 확인했다. 페이지별 스켈레톤이 표시됐고 이동 중 홈 제목의 DOM 출현은 0회였다. 이 브라우저 검사는 비로그인 상태에서 수행했다.

## 수정 파일 묶음

- `app/[locale]/(home)/page.tsx`, `app/[locale]/(home)/loading.tsx` 및 listings/reservation/wishList/trips/messages 하위 경로의 로딩 경계 6개.
- `app/component/Skeleton/`: 공통 상태 영역, 페이지별 스켈레톤, 이미지 플레이스홀더와 스타일.
- `app/client/home-client.tsx`, `app/wishList/WishListCard.tsx`, 채팅의 `ChatWorkspace.tsx` / `ConversationView.tsx`: 실제 페이지의 로딩 상태 연결.
- 목록 `SwiperComponent.tsx`, 상세 `DetailListingMainCarouselSwiper.tsx`, 예약 `ProductCard.tsx`: 이미지 로딩 처리.
- `KakaoMap.tsx`, 기존 `Loading.tsx` / `Spinner.tsx`, `styles/modern-ui.css`: 공통 로딩 처리 및 이전 스타일 정리.
- `tests/loading.test.cjs`, `tests/chat.test.cjs`, `package.json`: 회귀 검사와 실행 명령.
